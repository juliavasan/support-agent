# ServiceNow

Everything about the ServiceNow side of `support-agent`: instance, accounts, roles, knowledge base, authentication, setup scripts, and troubleshooting.

> **No secrets in this file.** It is committed to a public repo. Passwords live only in the gitignored `.env` and `.env.admin` files. Instance-specific values (URL, sys_ids) are in [`SERVICENOW.local.md`](SERVICENOW.local.md), which is also gitignored.

## 1. Instance

| Item | Value |
|---|---|
| Type | ServiceNow Personal Developer Instance (PDI), free |
| URL | `https://devXXXXXX.service-now.com`, in `.env` as `SERVICENOW_INSTANCE_URL` |
| Managed at | https://developer.servicenow.com → profile → *Manage instance* |
| APIs used | Table API (`/api/now/table/...`) only |
| Data | ServiceNow demo data plus our synthetic records. No real customer data |

**PDI lifecycle**
- **Hibernation:** the instance sleeps when idle. Wake it from the developer portal, which takes a few minutes.
- **Reclamation:** after roughly 10 days with no activity, ServiceNow can wipe the instance. Everything below can be rebuilt with `python3 scripts/servicenow_setup.py` (plus the data seeders, once they exist).

## 2. Accounts

| Account | Where it logs in | Used by | Purpose | Credentials stored in |
|---|---|---|---|---|
| **ServiceNow ID** (personal email) | developer.servicenow.com | You | Manage the PDI: wake, reset, upgrade | Your password manager |
| **`admin`** | Instance UI + API | You, setup scripts only | One-time configuration (users, groups, KB). **Never used by the agent** | `.env.admin` → `SN_ADMIN_PW` |
| **`support_agent`** | API only | The agent | Reads and works the incident queue | `.env` → `SERVICENOW_USERNAME` / `SERVICENOW_PASSWORD` |
| **Synthetic callers** | None | Seeded tickets | The "customers" who open incidents | No password. They don't log in |

### `support_agent` service account

| Setting | Value | Why |
|---|---|---|
| User ID | `support_agent` | |
| Web service access only (WSAO) | `true` | It can't log in to the UI, and it's exempt from the Basic Auth restriction (see §5) |
| Password | Random, generated by the setup script, never printed | |
| Direct roles | none | Access comes only through the group |
| Group | AI Support Agent | |
| Effective roles | `itil` (via group) | Read and write incidents, work notes, comments |
| Admin access | none | Verified: `sys_properties` read is denied |

### Synthetic callers *(to be seeded)*

Caller records are plain `sys_user` rows: name, email, company, location. They have **no roles, no password, and no login**. They only appear as the incident's *Caller*. They'll be imported from the synthetic user set (Phase 1 seeder). Use obviously fake domains such as `@example.com`.

## 3. Groups and roles

| Group | Members | Roles granted | Used as |
|---|---|---|---|
| **AI Support Agent** | `support_agent` | `itil` | The assignment group: the agent works only incidents assigned here |

Roles are granted to the **group**, not the user, so access is managed in one place and is easy to audit or revoke.

## 4. Knowledge base

| Item | Value |
|---|---|
| Knowledge base | **Customer Portal Support** (`SERVICENOW_KNOWLEDGE_BASE`) |
| Read access | User criteria **"AI Support Agent - KB read"** → group AI Support Agent |
| Contents | Synthetic articles for the demo customer portal *(to be imported)* plus one `support-agent KB access check` article used by the setup script |
| Out of scope | The instance's demo KBs (IT, Known Error, KCS demo, Knowledge). The agent can't read them, by design |

Why a dedicated KB: KB read access in ServiceNow is controlled by per-knowledge-base user criteria, not roles. Scoping read access to one KB keeps the agent's answers grounded in *our* synthetic content only and avoids a broad knowledge role.

## 5. Authentication

New PDIs enforce ServiceNow's **Basic authentication restriction**. A Basic Auth API request is rejected with `401 User is not authenticated` unless the account:

1. holds the `snc_basic_auth_api_access` role, **or**
2. is a **Web Services Access Only** account, **or**
3. supplies a valid MFA one-time code.

How we handle it:
- **`support_agent`** is WSAO, so Basic Auth works without any exception role.
- **`admin`** was given `snc_basic_auth_api_access` **temporarily** so the setup script could run. Remove it when you don't need to run setup (Users → admin → Roles). Re-add it only to re-run setup.
- **Production direction:** OAuth 2.0 client credentials (short-lived tokens, no stored password). See [DECISIONS.md](DECISIONS.md), ADR-006.

Reference: [ServiceNow Docs: Basic authentication restriction](https://www.servicenow.com/docs/r/platform-security/authentication/basic-auth-restriction.html)

## 7. Scripts

### `scripts/servicenow_setup.py`: provision the instance (admin)

```bash
python3 scripts/servicenow_setup.py
```

Idempotent. It creates whatever is missing and leaves existing records alone:

1. Group **AI Support Agent** with role `itil`
2. User **`support_agent`** (WSAO). If `.env` already has its password, that password is re-applied, otherwise a new one is generated
3. Group membership
4. User criteria, knowledge base **Customer Portal Support**, read access, access-check article
5. Writes the `SERVICENOW_*` values into `.env`
6. Verifies as `support_agent`: incidents readable ✅, our KB readable ✅, `sys_properties` denied ✅

Requires `admin` to have `snc_basic_auth_api_access` (§5) and `SN_ADMIN_PW` in `.env.admin`.

### `scripts/test_connection.py`: read-only connectivity test

```bash
pip install -e ".[dev]"     # or: pip install requests
python3 scripts/test_connection.py
```

Sends `GET /api/now/table/incident?sysparm_limit=5&sysparm_fields=number,short_description,description,state,priority,category,close_notes,sys_id&sysparm_display_value=true` with Basic Auth (TLS verification on), prints a table, and saves the response to `data/servicenow_incidents_sample.json` (gitignored). It never writes to ServiceNow.

Expected output:

```
GET https://devXXXXXX.service-now.com/api/now/table/incident  (user: support_agent, auth: Basic)
HTTP 200
Retrieved 5 incident(s) (X-Total-Count: 67)

| Number      | Short Description                             | State        | Priority     |
|-------------|-----------------------------------------------|--------------|--------------|
| INC0000060  | Unable to connect to email                    | Closed       | 3 - Moderate |
...
Saved response to data/servicenow_incidents_sample.json
```

Exit codes: `0` OK, `1` config or network error, `2` HTTP 401, `3` HTTP 403, `4` other HTTP error.

## 8. Troubleshooting

### HTTP 401: "User is not authenticated / Required to provide Auth information"

A working browser login or REST API Explorer call **doesn't** prove API Basic Auth works, because the Explorer uses your browser session. Check in order:

1. **Basic Auth restriction (most common on new PDIs).** The account must be WSAO, hold `snc_basic_auth_api_access`, or use MFA (§5).
2. **Password.** Log in at `<instance>/login.do` in a private window (not possible for WSAO accounts. Re-run setup to re-apply the password instead).
3. **Account state.** Active, not locked out, no *password needs reset*.
4. **MFA** enabled on the account also causes a 401 with Basic Auth.
5. **Instance asleep.** Wake it from the developer portal.

### HTTP 403: Forbidden

The account authenticated but lacks access to the table. Confirm group membership and the group's `itil` role.

### HTTP 200 with 0 rows

ACLs or user criteria are filtering the rows (the `X-Total-Count` header may still show the unfiltered total). For KB articles, check the knowledge base's *Can read* user criteria (§4).

## 9. Rebuild checklist (after a reclaim or wipe)

1. Request a new PDI. Update `SERVICENOW_INSTANCE_URL` in `.env`, and clear `SERVICENOW_PASSWORD` so a new one is generated.
2. Log in as `admin`, set a password, add `snc_basic_auth_api_access` to `admin`, and put the password in `.env.admin`.
3. `python3 scripts/servicenow_setup.py` should show three PASS lines.
4. Run the seeders (callers, KB articles, incidents), once they exist.
5. Remove `snc_basic_auth_api_access` from `admin`.
6. Update `SERVICENOW.local.md`.
